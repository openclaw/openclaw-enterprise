# Authorize a dedicated OpenClaw Agent’s model requests

**Approved design, pending installed qualification.** Use online request authorization for a dedicated OpenClaw Agent that needs an OpenAI model key and a separately granted saved plugin account. Withdrawing either grant must leave the other usable.

In the fresh Installation tested with stock OpenShell v0.1.7, OCC refused to register a new `openai` source because OpenShell lacked the protected static inference protocol. That revision of OCC also rejected a protected inference plan combined with a saved plugin account. The deployed plugin test used an existing Gateway-managed model source. [Registration and deployment evidence](https://github.com/openclaw/openclaw-enterprise/pull/4673#issuecomment-6692334499)

## Proposed delivery

1. **Register and bind the key.** In the Agent’s Credentials tab, the operator chooses a Namespace Secret. OCC checks the operator’s permission to use that Secret and the Agent’s grant on the source. The operator selects [online authorization](online-authorization.md) for the model binding. OCC records that choice with the provider, model and destination. The source records the reference to the existing Secret. The saved plugin account keeps its own binding and Token Service grant.
2. **Admit both bindings.** Ordinary worker admission binds the Agent revision and execution to the selected providers and routes. The guest gets opaque placeholders. Before launch, verify that the supervisor enforces both routes, that each identifies one binding, and that the workload cannot bypass them. Qualify the actual OpenClaw request method, path, transport, model and request body. Deny unapproved fields such as provider-hosted tools that can call another service. Refuse overlapping credential routes.
3. **Authorize the request.** The OpenShell supervisor runs the pre-credentials middleware on the actual request before it injects credentials. OCC records an approval for the admitted binding. The supervisor requests the credential through zero-cache `token_grant`. When selected, a short-lived OpenShell Gateway-signed assertion identifies the Sandbox for that execution, the provider and the credential key. SPIFFE authentication remains available where selected. The request ID correlates the exchange. [Optional Gateway assertion](https://github.com/NVIDIA/OpenShell/pull/5479)
4. **Release and send.** The OpenShell Credential Proxy Driver authenticates the assertion. OCC consumes one approval matching the authenticated recipient, request ID, binding, Driver and expected credential identity. It rechecks current authority and credential version before releasing the model key from the Secret Driver or the [saved account token](../0027-agent-oauth-connections/contracts.md) from Token Service. The supervisor sends the request. Consumption alone proves neither credential release nor dispatch. The approval deadline bounds release. The provider controls the lifetime of the underlying credential.

If OCC observes withdrawal at the release check, it refuses to release the credential even if it previously approved the request. A request the supervisor has already sent can finish. A revision that requires [exact dispatch](protocol.md) must still bind the credential, send attempt and response to the execution. Coordinate the model profile with [static inference retirement](https://github.com/openclaw/openclaw-enterprise/issues/4437) and [Credential Gateway retirement](https://github.com/openclaw/openclaw-enterprise/issues/4843).

## Qualification before enabling the profile

The [model authorization change](https://github.com/openclaw/openclaw-enterprise/pull/5231), [Git placeholder change](https://github.com/openclaw/openclaw-enterprise/pull/5345) and [installed assertion test](https://github.com/openclaw/openclaw-enterprise/pull/5423) cover related work. The test pairs Codex with Git at controlled origins. It calls for a model turn, a Git fetch, denial after Git withdrawal and another turn in the same conversation. The dedicated OpenClaw model and saved plugin account still need the following installed proof.

Start from a fresh Kubernetes Installation with Credential Proxy selected. Register the model key, connect the plugin account through browser consent, and deploy through the ordinary worker. Run a real model turn that calls the selected plugin tool. Verify which credential each HTTPS service received and that the guest sees only placeholders. Exercise the model transport the Harness actually uses, including streaming if the turn uses it.

Deny a different model or destination, a redirect carrying credentials to another host, an unselected tool, and replay of a consumed approval. Rotate each credential independently. Verify the replacement at its origin on the next request and continued access through the other binding. Withdraw Agent A’s model grant while the key remains valid at the provider. A’s next model request must miss the origin and its plugin must still work. Agent B must retain its independently granted model access. Separately detach A’s plugin account. A must retain its model access in that case and Agent B must retain its plugin access. If stock OpenShell cannot enforce a required boundary, keep that profile unavailable and name the missing sender capability in the implementation PR.
