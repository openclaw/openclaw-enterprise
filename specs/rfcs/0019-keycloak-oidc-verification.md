## 1. Decision and scope

Propose production human sign-in with operator-managed Keycloak through [OCE's existing OIDC integration](0001-oidc-sign-in.md). The operator owns Keycloak, its realm and users, durable database, DNS, TLS, administration, backups, upgrades and availability. The selected initial route uses an existing publicly trusted HTTPS certificate; the OCE chart connects to it, but does not install Keycloak. Private-CA support is required before OCE 1.0 and proceeds separately in [#1774](https://github.com/openclaw/openclaw-enterprise/pull/1774); it does not block initial Keycloak delivery. A dedicated main-based chart implementation is under review; it is not merged or production-qualified.

An opt-in Local Setup profile and real-provider CI use a shared disposable development fixture, not the production realm. This adds no managed IdP, just-in-time accounts, claim mapping, Agent OAuth or token refresh. Service keys and Agent credentials remain separate. Free has accepted this bounded scope, including the documented recovery and native-administration restrictions. Production qualification and human RFC merge remain pending.

## 3. Operations and environments

**Production.** Protect and verify a password recovery administrator, configure the client and OCE Secret under [stopped maintenance](../../docs/guides/deploy/oidc-sign-in.md#configure-the-chart), and attach enterprise subjects. Verify each person's browser sign-in and permissions, plus unattached-user denial. Password sign-in defaults to `all`; move to `recovery-only` only after verification. It restricts new password sign-ins, not existing sessions. Keep the recovery password available during IdP outages.

Coordinate client-secret rotation at Keycloak and the OCE Secret, then restart the API; attachments persist and pending attempts are invalidated. Signing-key rotation uses freshly fetched JWKS on each callback without an API restart. An issuer or client-ID change requires reattachment. Follow the [stopped-maintenance rotation procedure](https://github.com/openclaw/openclaw-enterprise/blob/80d72a3373c1eb5a1acc54caf703fb41d71de36a/docs/guides/deploy/oidc-sign-in.md#changes-rotation-and-outages).

**Local and CI.** The opt-in profile requires Kubernetes compute and control plane, `OCC_DEVELOPMENT_SANDBOX_DRIVER=none` (local only), loopback port 443, browser CA trust and a hosts entry. Its realm persists across restarts; `occ dev down` destroys it, and fixture replacement requires teardown. See the [local guide](https://github.com/openclaw/openclaw-enterprise/blob/4eadb9782cda33b4e891ae277a81f50b0bec4958/docs/guides/deploy/local-kubernetes-development.md#sign-in-through-keycloak) and optional [detailed local flow](../assets/0019-keycloak-oidc-verification/request-lifecycle.svg). CI uses the same digest-pinned development fixture, currently Keycloak 26.7.5; this does not qualify every 26.x deployment.
