# Acceptance criteria and delivery of the repository token Source

Use an installed OpenShell environment, an authorized administrator, saved Agents and a controlled Git origin that accepts test tokens. Keep the old token valid at the origin when testing withdrawal. Otherwise a refusal at the origin could hide a credential the Sandbox still sends. The [proposal](index.md) defines [goals G1–G5](index.md#goals). [Lifecycle](lifecycle.md) describes what the operator should see.

## Acceptance Criteria

- **AC-1 (G1, G5). Per-repository Git access.** Repeat the [network policy](../20261119-repository-network-policy.md#acceptance-criteria) Git tests. Read A, read and push B, deny C and deny a push to A. Narrow B to read, check the saved policy and try the push again. For every denial, including direct REST and GraphQL, count zero requests at the origin. Verify the Provider has no endpoints and the Sandbox binds exactly the saved paths. Repeat the existing App journey unchanged.
- **AC-2 (G2). Keep the token private.** Inspect process environments, command lines, Git configuration and files after deployment and replacement. Neither the Agent nor a peer Agent can see the PAT.
- **AC-3 (G3). Rotate in place.** Record separate times for commit, pending delivery and confirmation. Read pending then confirmed in the policy. Verify confirmation follows the target supervisor's report. The origin receives the new value without a redeploy. Repeat AC-1's API denials, zero requests, endpoint and binding checks. Try a classic token. `PATCH` refuses it and the prior value still works.
- **AC-4 (G4). Order writes.** Pause the Worker during replacement and again during retirement. A stale write must never restore the old value or extend access. Lose a Provider response. Replacement and deletion must return `409`, even after a Worker restart. A caller who can read the Agent sees its ID and revision. A caller who cannot sees only a count and a reason. A metadata edit succeeds. Stop or redeploy, confirm Provider removal and verify the block clears. Even a late write expires within 15 minutes of its authority check or at grant expiry, whichever comes first.
- **AC-5 (G4). Measure withdrawal.** Remove the Agent principal's authority with the Worker connected. Time both the refusal to renew and the last authenticated Git request. Verify prompt withdrawal separately from expiry. Then prevent renewal during an outage. Show that the supervisor stops injecting by the deadline while the origin still accepts the PAT. Repeat with a shorter configured limit. A peer Agent keeps working in both cases. The maximum stays provisional until verified.
- **AC-6 (G4). Deny new access and allow cleanup.** Exercise each [save, validation and deploy refusal](lifecycle.md#save-and-deploy), including a missing policy and differing permissions. Verify no legacy fallback. Remove the Agent principal's `operate` and check the next loan fails. Clear grants and stop with a missing or unready Source and after the caller loses Source access. No request carries the PAT after Stop. A reader without Source `read` sees saved grants, version and Installation ceiling, with no Source ID, name, state, ceiling, effective access or delivery state. Deletion fails with `409` while the registry names the Source.
- **AC-7 (G2). Keep Git and model credentials separate.** On bound and unbound Sources, try adding, removing or replacing the Git preset and clearing its config. Each forbidden change returns `409` and leaves the Source intact. Reject a Git Source in Connection Templates, Plugin and model delivery, Harness authentication and the Agent's `credentialSources`.
- **AC-8 (G4). Retire after registry removal.** Remove a running Agent's Source from the registry and restart the controller and Worker. Before cleanup, deletion returns `409`. A caller who can read the Agent sees which copy blocks deletion. The Worker rejects the stale binding, removes the Sandbox and confirms the Provider is gone. Deletion now succeeds and no request carries the PAT. Repeat with a queued deployment and with a Worker restart during retirement.
- **AC-9 (G5). Start without an App.** Run the [cold setup test](#cold-setup) for Read. Separately, register a Write-capable Source explicitly and load a Source-only registry without an App key Secret. The controller and Worker start. A saved Agent reads and pushes. Keep the existing refusal when an App has no valid signing key. An installation with a valid App must still work.
- **AC-10 (G1). Use one permission set.** Select two registrations with one Source, Contents read on A and Contents write on B. Save and deploy each return `409` naming the difference. Give both registrations the same permissions, save read on A and write on B, deploy and repeat AC-1.

## Cold setup

For AC-9, use a clean host profile with no GitHub CLI login, App key, existing installation or repository registry.

1. Run `occ dev up --github-repo acme/docs` with a test PAT on standard input. Record elapsed time to a usable catalog. Verify one ready Source and a matching native Git Read registration in the new Namespace. No file editing, copying of IDs or additional setup command should be necessary.
2. Confirm that an Agent without the grant cannot clone. Save Read, deploy and clone through the ordinary Git client. Record the first successful clone and verify its commit against the origin. Push, a second repository, REST and GraphQL must produce zero origin requests.
3. Repeat AC-2 and inspect terminal output, setup files, Helm values and logs. Check that a different ambient GitHub CLI login is never used. Reject missing input, an OAuth or classic token, a malformed repository and a policy that admits extra traffic.
4. Point the launcher at an existing installation or a mismatched endpoint. Verify no credential is sent and no existing state changes. Simulate mismatched Source metadata, a lost create response and a stale catalog. Each must prevent success without duplicate enrollment or wider grants.
5. On an existing installation, run `occ credential-source create --github-repo acme/docs` separately. Check that only enrollment occurred. Complete explicit registration and Agent selection, then repeat the clone.

## Delivery and verification

The [previous RFC revision](https://github.com/openclaw/openclaw-enterprise/blob/5ba097b1b6f7c704bf627627eb122e0c9be6e74f/specs/rfcs/20261123-repository-token-source/acceptance.md) records the results below across several drafts. They predate [#7224](https://github.com/openclaw/openclaw-enterprise/commit/105ffee9962176cf42fc7cfe013b8b94831435db). Neither shortcut nor the delivery path on this baseline has installed evidence here. Repeat the full matrix and check upgrade compatibility against the current migration catalog.

- **[Source registration #7152](https://github.com/openclaw/openclaw-enterprise/pull/7152) and [native Git delivery #7153](https://github.com/openclaw/openclaw-enterprise/pull/7153).** Registration alone cannot deliver a token. Installed runs with a controlled origin exercised parts of AC-1–AC-6, AC-8 and AC-9. They include startup after switching an existing installation to a registry without an App key, an App regression run and automatic cleanup after registry removal. The switch alone does not prove a fresh local installation without an App. AC-7 and the mixed-permission refusal in AC-10 have test coverage only. The queued deployment and mid-retirement restart cases in AC-8 still need cluster tests.
- **Lost response, AC-4.** At [a448eac9](https://github.com/openclaw/openclaw-enterprise/commit/a448eac9fdc6ac4040a37f89907432d5da8bf421), the real Gateway applied a write and its response was dropped. Replacement and deletion stayed blocked through Worker replacement until Stop retired the copy. The origin never saw the older value again. This case does not cover a write that first takes effect after the lock ends.
- **Withdrawal, AC-5.** With a healthy connection and [b733005e](https://github.com/openclaw/openclaw-enterprise/commit/b733005eb583af8d1cf501b59a1185a850b252f6) product code, the Worker denied renewal in 4–6 seconds. Git failed 485 and 599 seconds after revocation in two controlled runs. Those observations measure the existing loan's expiry. Prompt withdrawal, the shorter configurable limit and the full outage test remain open.
- **GitHub without an App.** At [c0c1b146](https://github.com/openclaw/openclaw-enterprise/commit/c0c1b1460e2993e24c3d769fd2acc1bacffe699e), a dedicated fine-grained PAT worked for a private repository. The run covered read, push, REST and GraphQL denials, replacement, withdrawal and retirement. Renewal was refused after 7 seconds. Git failed after 517 seconds, with HTTP 500. The run predates the uncertain-write fix. An earlier file-based prototype covered only parts of AC-1–AC-3.
- **[Policy read #7202](https://github.com/openclaw/openclaw-enterprise/pull/7202) and [Console #7216](https://github.com/openclaw/openclaw-enterprise/pull/7216).** The API draft moved confirmation from Gateway acceptance to Sandbox activation. Installed checks saw `pending`, `confirmed` and `unreconciled` (AC-3, AC-6). Redaction for a caller without Source read access still needs an installed check. The Console draft displays this policy.
- **Upgrade.** An Installation upgraded from an earlier main through the delivery and policy drafts with an App Agent and a Source Agent running. The copy record survived. This does not establish renewal after Worker replacement.
