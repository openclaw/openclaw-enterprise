# GitHub App integration and acceptance

## First implementation PR

For the first integration, give a running Agent read/write access to repository A and read access to B. The operator makes repositories eligible in the Namespace and the Agent owner selects them in `repositoryBindings`. Today, one permission map applies to all repositories in an Agent’s selection. For the installed test, resolve separate permissions for A and B, covering both code and issues. GitHub enforces branch and tag rules. [Current enrollment](../../../docs/guides/repository-credentials/openshell-enrollment.md)

Start with one repository and one permission tier. Adapt the scoped request builder, App JWT exchange and HTTPS fixture in OpenShell’s open [GitHub App strategy](https://github.com/NVIDIA/OpenShell/pull/3676) to the issuer library. The candidate signs inside the gateway, reads only the returned token and expiry, and treats a lost response body after HTTP 201 as retryable. Move signing into the issuer and retain OCE’s [candidate capture](../../../apps/controller/src/drivers/repo/github/credentials/prepared-owner.ts) and [returned-scope validation](../../../apps/controller/src/drivers/repo/github/credentials/installation-token-response.ts). Use an issuer-owned fixture key. The connected test requires a separate service. Keep GitHub permission names and JWTs inside the strategy so the OCC grant can also serve GitLab. [Candidate exchange and failures](https://github.com/NVIDIA/OpenShell/blob/63815b5f540339f3ebcd3bdfabce0715f23e4555/crates/openshell-server/src/provider_refresh/github_app.rs#L145-L220)

- Verify the successful POST contains the exact repository and permissions. Derive mint and revoke URLs from the trusted GitHub instance. Reject endpoint overrides and redirects. With a second test origin, verify it receives neither a request nor a credential.
- Drop the reply after the fixture receives the POST. Restart, advance past retry time, run a due sweep and request rotation. Reconfigure the same provider and credential key with a fresh request ID, then run another due sweep and manual rotation. Across all of these steps, expect one total POST and zero published outputs. In a separate case, return an overprivileged token. Verify zero delivery and revocation of that exact token.

## Connect OCE before cutover

Use OpenShell’s proposed RPCs with two authenticated control-plane clients. The enrollment client provisions the signer at the issuer and calls `CreateGrant`. The issuer binds the authenticated workspace, grant generation and named output to OCC’s resolver identity. This delegation extends the draft’s caller-owned references. A gateway or ordinary resolver that knows the signer reference still cannot read the key or use it to sign.

For authorized delivery, extend `EnsureFresh` beyond operator export. OCC supplies the registered grant, expected generation, minimum remaining validity, deadline and operation ID. The issuer returns the committed output reference and version after joining or completing any required mint. OCC calls `ResolveSecrets` for that output, matches the response to the owner-scoped request and checks its version and expiry against the selection, and rechecks current authorization. A changed version requires a fresh resolution. For a static key, read the authorized version directly. Only the issuer calls `TokenMinter.Mint`. [Proposed RPCs and identity rules](https://github.com/NVIDIA/OpenShell/blob/e7f04cbf5846ce3083bf4f8e479b68e2341cb216/rfc/0023-credential-issuer-service/README.md#credentialrefresh-contract)

For the first connected test, enroll a key at the separate issuer. Start with an approved repository grant and no issued output for it. Send one permitted Git request through the supervisor proxy. Observe an OCC decision, one issuer-to-GitHub mint, an approved short-lived output returned by OCC, and one send by the proxy. Prove that the credential gateway cannot read the key, obtain a signed App JWT, call the signer or select another installation. A local fixture cannot establish that boundary.

At enrollment bind the signer to the trusted GitHub instance, App, repository-bearing installation, eligible repositories and permission ceiling. Only OCC’s authenticated control-plane resolver or its explicit delegate can request a mint for an approved grant. Enforce these limits for every issuance trigger, including renewal and manual rotation. Reject a proxy that presents a valid workspace identity and signer reference but requests another Agent’s authority. Reject enterprise-account installations for this strategy. Only the issuer needs egress to GitHub’s mint and revoke endpoints. [GitHub installation types](https://docs.github.com/en/enterprise-cloud@latest/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)

On this proposed Git route, one sender call asks OCC to authorize and resolve the captured request. The signed metadata path already lets an authorized cold request start or join GitHub issuance. The native broker reads prepared material. The installed OpenShell Git hook returns an operation decision for material installed earlier. Extend the supervisor’s trusted send path to hold the captured request, bind OCC’s selected credential to its repository and operation, and inject it into that same request. The current Boolean allow cannot select between A-write and B-read. Qualify this sender separately from RFC-0023’s exact-dispatch protocol. [Token Service integration](https://github.com/openclaw/openclaw-enterprise/pull/4853) · [Git sender boundary](https://github.com/openclaw/openclaw-enterprise/blob/d75f285fa0100ba8aa732212156d5876aa7e0e72/docs/design/credential-proxy-architecture.md#proposed-git-credential-pull)

Bind control-plane writes to the expected provider instance and generation. Test two late mints. Withdraw a grant on the same provider instance. Separately, replace the named provider while its grant stays approved. In each case OCC must withhold the stale output. The original issuer owns revocation or records uncertainty. An independent Agent must still succeed.

Control-plane resolution must deny a swapped placeholder, a client-supplied bearer or an ambiguous cross-repository API request. Interleave A writes and B reads on the same Agent. Verify that each send uses the credential for that repository and permission tier. Neither Agent credentials, snapshots nor export APIs available to the Agent may reveal a provider token. Additional API path restrictions and disabling GraphQL remain operator options. Public reads can remain anonymous where permitted. Existing `git-write` grants retain their exact-ref restrictions.

Remove the OCE signer, exchange wiring and worker key mount after the last callers move and outstanding tokens and operations settle with their original owner. OCC retains repository policy and per-Agent grant checks. Retire the other credential paths as each family moves through the [migration plan](../../plans/0030-openshell-credential-service.md).

## Authorization across senders

For v1 each backend enforces its native egress policy, then its trusted sender asks OCC about the actual request. Defer caching both approvals and credentials at the sender. The Token Service may reuse the issuer’s committed output for the same grant. Existing exact-dispatch admissions still require a one-use send permit. [OCE exchange contract](https://github.com/openclaw/openclaw-enterprise/blob/f1c0865be4c523090af0dccc29c613ad1d47d542/packages/contracts/src/credential-proxy-exchange.ts)

Git read and write discovery can both use `GET /owner/repo.git/info/refs`. The `service` query distinguishes `git-upload-pack` (read) from `git-receive-pack` (write). OpenShell exposes the raw query to its request hook. Box’s native HTTP policy effect exposes the method and path without the query. Its OCE reference sender exercises a bounded model POST. For Git, each adapter must classify the request it will send and bind it to the authenticated execution. If a backend cannot distinguish the operation, refuse that protected route. GitHub enforces branch rules. For an existing exact-ref grant, the adapter must also inspect every ref command in the receive-pack body before forwarding. Deny an unsupported exact-ref push. Test one allowed and one forbidden ref in a single push and expect zero upstream sends. [OpenShell request target](https://github.com/NVIDIA/OpenShell/blob/2856eef417c50de6375852e8175ab0a6dc0011b8/proto/supervisor_middleware.proto#L602-L625) · [Box policy effect](https://github.com/strands-agents/box/blob/c8856a1aa60e8e024101fad06336ef52c7e9bedd/crates/egress-gateway/src/effect.rs#L90-L130)

For a future read-only trial, let OCC define which captured requests have equivalent authority. Limit the first candidate to bodyless Git read discovery. Match these facts together:

- Installation and Namespace, acting principal and delegation, admitted Agent execution, authenticated sender installation and recipient.
- Effective policy and plan versions, source binding and grant generations, issuer and output version for a cached credential.
- Verified origin, immutable repository ID, route and classifier version, classified operation, and all query, header and response restrictions that affect that route.

Keep request IDs, connection, response recipient checks and one-use permits bound to each send. Recheck local policy and the actual destination on every hit. Do not reuse a read for another Agent, recipient, redirect, write or ambiguous request. Expire the pair at a fixed deadline capped by execution, grant, policy and credential validity. Evict on observed changes. A partition can hide a newer generation until expiry. Qualify these semantics on both senders and measure OCC round-trip savings before adding either cache.

## Recover a missing reply

- **The proxy lost OCC’s credential response.** Without a usable response the proxy sends nothing. If the request is still eligible, it asks OCC for a fresh decision. OCC checks current access and reuses the known committed output or reconciles the original mint. Test by dropping the response after a successful mint, withdrawing the grant, then retrying resolution. Expect one mint, zero Git sends and a denial. A possible Git send has its own recovery path below.
- **OCC lost the issuer’s reply.** Persist the issuer, authenticated caller, workspace, method, operation key, grant generation and input fingerprint before dispatch. Retry that identical operation. The issuer returns its original grant, output references or committed versions, joins an in-flight attempt, or reports an uncertain outcome. Reject changed input. The request deadline bounds new work and waiting. After timeout, replay may read the original committed receipt within its retention window under current authority. Never start another mint on an expired deadline or treat an expired key as new. `GetGrant` needs a known grant handle; it cannot recover a creation reply that contained the only copy of that handle. The draft has idempotency keys for `CreateGrant` and `PutSecret`. Require the same recovery behavior for delivery-triggered issuance and qualify it on the remote service. Recheck access before releasing any result.
- **GitHub may have minted.** The issuer records intent before the POST. It can retry a proven unsent call under current approval. Park uncertain attempts across restart, scheduled refresh, manual rotation and reconfiguration. GitHub offers no documented mint deduplication by attempt ID. Quarantine identifiable rejected or superseded tokens for revocation at GitHub. If no token came back, keep the original grant unavailable until the issuer can establish non-issuance or expiry and exclude a late publication. Local deletion or a new grant name cannot settle the old attempt.
- **GitHub may have accepted a push.** The sender reports an unknown outcome. The caller reads the target ref through an authorized path and compares the expected SHA before deciding on another push.

## Local development and CI

For v1, the developer or CI runner checks out the repository and gives the Agent a working tree free of runner credentials. Give the Agent no GitHub credential. It edits, tests and returns a patch without a proxy or cluster. In GitHub Actions, set `persist-credentials: false` and omit runner tokens from the Agent environment. A separate trusted step can publish the patch. Use k3d when testing the Kubernetes deployment and its network policies. [Checkout settings](https://github.com/actions/checkout#usage)

If a job needs live private Git, first try the [existing Compose client and broker](../../../deploy/examples/repository-credentials/compose.yaml). The [development profile](../../../docs/reference/repository-credentials/development-token.md) keeps a host-supplied GitHub token in the broker and gives the client a short-lived repository session. Put the Agent only on an internal network and attach the broker to that network and an outbound network. Keep host networking, runner credentials, and the Docker and broker control sockets out of the Agent. From the same Agent, fetch a known private ref through the broker, then try a direct TCP connection to the GitHub address and port the broker reached. The fetch must succeed and the direct connection must fail. [Compose internal networks](https://github.com/compose-spec/compose-spec/blob/main/06-networks.md#internal)

For managed Git, the [native broker](../../../docs/reference/repository-credentials/prepared-native-git.md#what-a-request-authorizes) serves dedicated Codex on Kubernetes. To use it in plain CI, the runner would need to bind a short-lived session to an admitted Agent execution, deliver it to that job, and demonstrate denial after withdrawal. Defer this work if it requires new workload admission or a general egress proxy. Both live-Git options are optional for v1.

## Installed acceptance test

The OpenShell supervisor is the first sender. A second implementation such as [Strands Box](https://github.com/openclaw/openclaw-enterprise/pull/4007) must demonstrate its own execution binding and egress enforcement. Protected Git still requires a trusted sender when OpenShell is absent. In each managed deployment, verify that a direct connection cannot bypass the trusted sender for a protected request.

Use the separate issuer service, OCC and the OpenShell supervisor proxy. Observe the scoped mint at the issuer and the protected Git request at the sender. Verify a static-source request invokes no minter, a denied cold request invokes no mint, and an unavailable OCC or issuer yields no unauthenticated fallback. Use one organization installation with access to private A, B and C. Verify independently that C is readable and the App can write the test branches on A and B. Disable alternative credentials. Give Agent 1 A-write and B-read and give Agent 2 an independent A grant.

1. Push a unique commit from Agent 1 to A. An independent reader sees its SHA.
2. Read a known private ref in B. Then try to push to B. The push fails and the remote SHA stays the same.
3. Try to read C from Agent 1. Access fails while the independent reader still reads C.
4. With TTL zero, keep an HTTPS client open and record its connection ID. Withdraw all Git grants from Agent 1 while the material is valid. Repeat a previously allowed request over that connection. Observe the withdrawal denial and zero GitHub requests for the attempt. Get a fresh model reply in the same execution and chat and a fresh private read of A from Agent 2.
5. Run this case only for a profile that explicitly enables a positive authorization TTL. Start with an active grant and prime only Agent 1’s A read-discovery entry. Isolate its proxy from OCC and withdraw the grant. A matching read may still succeed before the recorded expiry. An A-write must miss and fail. After expiry, repeat the read: the proxy must deny it with zero new GitHub requests. Restore connectivity and verify that OCC still denies it.

Keep the chat running when the operator can verify Git-only detachment and independent model access. Retire the execution if Git access cannot be isolated.

For issues, read and update a test issue in A, read one in B, then try to update it. Verify B’s issue is unchanged after the denied write. Record identities, expiry, decisions and ref SHAs without token values. This installed test remains to be run.
