# Implementation plan: Managed OpenClaw plugins

- **ID:** RFC-0031
- **Delivery status:** In progress
- **Authority:** [Managed OpenClaw plugins](../rfcs/0031-managed-openclaw-plugins.md)
- **Source audit:** `8b9b105b6398b8ad2d62c49d016c008bbd406d93` on 2026-11-09; source and PR status, not a new runtime qualification.

## Outcome

An operator configures a reusable account, selects reviewed CLI or hosted MCP plugins, selects MCP tools where applicable, and deploys an OpenClaw Agent. Native calls and admitted scripts obey the credential binding's request policy. Account renewal, worker replacement, plugin removal, and independent credential attachments follow their owning lifecycle.

The RFC owns the design and boundaries. This plan records delivery and verification. Existing merged work is the baseline; open PRs remain incomplete until their supported workflow is qualified.

## P0: complete the connected-account workflow

1. **Grant Agent access to a saved account and bind it to a slot.** The operator can select a saved account or start consent from the Agent editor. OCC must recheck the caller, slot and release before attachment. Discovery and credential delivery must enforce the exact Agent grant and selected recipient. Detaching one Agent must preserve other grants. The implementation under review includes saved-account delivery through Credential Proxy and discovery on the Create Agent form. [#4673](https://github.com/openclaw/openclaw-enterprise/pull/4673)
2. **Qualify the connected account through ordinary deployment.** Exercise consent, deployment, a successful native tool call, a denied script call, renewal, and withdrawal on the same Agent. Verify the API and background renewal worker can reach the configured OAuth endpoints in the installed network configuration. Update the [live support page](../../docs/reference/managed-openclaw-plugins.md) with the implementation that ships. [Deployment qualification](https://github.com/openclaw/openclaw-enterprise/issues/4819)

The open implementation has recorded real Slack consent, discovery of 27 tools and deployment in a Kubernetes lab. Its documented UI turn stopped during Gateway tool assembly on the optional `action` argument of `slack_update_canvas`. Successful native Slack use on that recorded configuration remains a qualification step. [Branch evidence](https://github.com/openclaw/openclaw-enterprise/pull/4673)

CLI dependencies may require image construction. | Custom MCP and discovery egress                          | Connection/Plugin/Sandbox owners admit configurable endpoints and resources; provide discovery egress from OCC that supports those endpoints without broadening Helm networking arbitrarily. | Credential access visibility and custom scopes           | Credential/Console owners show source references, placeholder names, effective destinations, operations, and deployment state without values. A custom scope requires a corresponding approved endpoint allowlist and enforceable request rules; selecting a scope alone adds no route.                                                                                           |
| Google product/action controls                           | Connector/Console owners derive product-grouped scopes and supported actions from the pinned operation inventory, then expose them in the UI. Extend provider credential modes only with their own runtime proof.                                                                                                                                                                 |

Preserve explicit grants and per-Agent isolation; reject combinations whose effective restriction cannot be enforced. | Invocation approval and elicitation                      | Harness/Plugin owners implement the approved request-time gate, trusted action classification, reviewer routing, and bounded approvals. Keep this separate from Harness credential injection.                                                                                                                                                           |

Cache public schemas by API version when measurements justify it; no credential accompanies public schema fetches.                                                                                                                      |

## Verification

Use a real authorized account and the normal Console flow on an OCE-deployed Agent. Record which revision, provider grant, and enforcement path each result exercises.

- **Connect and deploy.** Create/select a template and OAuth client, consent, choose a saved account from a plugin slot, discover/select MCP tools where applicable, and deploy. Verify the actual selected resource, scopes, runtime image, and saved Agent revision. No secret appears in Console responses, artifacts, model context, or logs.
- **MCP allow and deny.** With a grant that offers both allowed and disabled tools, verify an actual Agent tool result and an equivalent admitted script call. Attempt the disabled upstream tool directly and verify zero upstream calls. Change the selection in Console, redeploy, and repeat. Exercise reconnect and expired-token renewal through the same credential owner.
- **Google allow and deny.** Verify a supported operation through gog and an approved direct-HTTP script. Deny an operation outside the binding, including a disallowed parameter on an otherwise allowed route. Use a sufficiently broad provider grant so provider scope rejection cannot masquerade as OCE enforcement.
- **Lifecycle and isolation.** Replace the Harness, start a fresh conversation, and verify selected artifacts, policy, and workspace reuse. Detach an account from one Agent and verify new requests fail after confirmed withdrawal while another authorized Agent/attachment remains usable. Removing a plugin must preserve independently retained credential access and worker recovery. Exercise account refresh failure and scope narrowing.
- **Policy boundaries.** Refuse unapproved destinations, unsupported operations, overlapping MCP routes, malformed requests, and incompatible Sandbox/Proxy combinations. Verify account changes invalidate stale discovery and credential material remains outside Gateway tool metadata.

Record sanitized request counts/results, the tested release and policy, actual runtime versions, and the final PR head. Keep a short Console recording beside the implementation PR. Broad Google coverage, arbitrary MCP argument constraints, new providers, and alternative enforcement adapters require their own checks as they are added.
