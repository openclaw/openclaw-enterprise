# Feature Spec: Milestone 1.7 — Local Test Drivers

## Problem and Decision

The selected development Compute Driver reports deterministic readiness but
starts no real gateway or Agent workload. Milestone 1.7 introduces one test-only
`LocalTestComputeDriver` that resolves and validates both pinned runtime
binaries once, reconciles one OpenClaw gateway per Namespace, and supervises one
isolated Codex harness per admitted AgentRevision.

The Compute Driver owns executable resolution and both infrastructure
lifecycles. OCC retains authorization, immutable admission, and active-revision
truth. A Driver-owned Namespace route guard consults that truth on each test
request before forwarding to the prepared workload, so an idle prepared
candidate cannot serve before activation and the existing worker needs no
activation callback, recovery scan, or new queue.

Build on [Agents and immutable AgentRevisions](1.6-agents-and-immutable-agent-revisions.md)
and the existing [OCC controller](1.5-occ-controller.md). The
[platform design](../../../../docs/design.md)
remains authoritative. `KubernetesComputeDriver` remains the only supported
production implementation.

## Scope

### Changes

- Add a test-only `LocalTestComputeDriver` under
  `apps/controller/src/drivers/compute/local-test/` implementing the existing
  four-method `ComputeDriver` contract without a new workspace package.
- Exclude that subtree from the controller's production TypeScript build and
  verify it through a separate strict, no-emit test-only TypeScript project.
- Resolve and validate explicitly configured pinned Codex and OpenClaw
  executables once through the Driver-owned test-runtime bootstrap; reuse its
  memoized result without downloading, copying, or caching executables.
- Run exactly one Namespace-owned OpenClaw gateway and independent,
  revision-owned Codex harness processes with deterministic cleanup.
- Select the same test Compute identity and Harness descriptor in authorized API
  admission and the controller worker.
- Route a request only when trusted OCC state identifies its exact Agent and
  revision as active in the gateway's Namespace.
- Verify lifecycle behavior exclusively with mandatory real Codex and OpenClaw
  startup without provider credentials; fail explicitly when either binary is
  unavailable.

### Does not change

- The singleton Installation, exact Namespace and Agent ownership, OCC-owned
  identity, IAM authorization, immutable revisions, or active-revision truth.
- Existing `ComputeDriver` methods, reconciliation targets, durable queue
  schema, claim fencing, per-Agent lanes, or Namespace gateway cardinality.
- Production Driver registration, production builds, deployment configuration,
  Kubernetes compute, production sandbox enforcement, or workload credentials.
- Additional Harness or Gateway Drivers, platform-caller-selected binaries, live
  provider credentials, external model integrations, or archived `legacy/` code.

## Contract

See [Contract](1.7-local-test-drivers/contract.md#contract).

## Implementation

1. Add the test-only Compute implementation and its memoized binary resolver
   under `apps/controller/src/drivers/compute/local-test/`, inside the existing
   controller workspace; require both real per-binary paths, support
   independent exact-version pins, exact parsed version validation, runnable
   OpenClaw gateway validation, isolated probe directories, and memoized
   executable resolution.
   Exclude the subtree from the production controller build and verify it with
   `apps/controller/tsconfig.local-test.json`.
2. Implement Namespace-owned OpenClaw gateway supervision and revision-owned
   Codex harness supervision against the existing
   [ComputeDriver contract](../../../../packages/contracts/src/index.ts), with
   exact ownership, safe resource ID paths, per-resource single-flight launches,
   loopback-only endpoints, isolated state, exit-confirmed teardown, and
   shutdown that drains in-flight starts before removing runtime state.
3. Inject a trusted read-only `isRevisionActive` resolver into the local Driver;
   run a Driver-owned loopback HTTP proxy in the parent process that checks the
   exact ownership tuple and workload health on every request, strips caller
   credentials and hop-by-hop headers, then authenticates forwarding to the
   exact Namespace gateway without changing the controller worker.
4. Reuse existing [worker injection](../../../../apps/controller/src/worker.ts) and
   controller registration points so tests select the same Compute identity and
   Harness descriptor explicitly without changing production registration.
5. Verify lifecycle ownership, activation-gated routing, credential exclusion,
   a ready OpenClaw gateway, and an initialized Codex app-server without
   provider credentials in the mandatory
   real-binary integration test (historical path:
   `tests/integration/local-test-compute-real.test.mjs`).
   Fail that test when either explicit binary path is missing; exercise
   persisted API/worker selection with the same real executables in the
   PostgreSQL local-test composition test (historical path:
   `tests/integration/postgres-local-test-composition.test.mjs`).
6. Document mandatory explicit binary configuration, one-time validated path
   resolution, test-only execution, credential boundaries, troubleshooting, and
   the unchanged production boundary under [docs](../../../../docs).

## Verification

| Required outcome         | How to verify                                                                                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compute-owned resolution | Select both independently pinned real executables; confirm their exact paths and versions and one memoized bootstrap across repeated reconciliation.             |
| Explicit binary paths    | Run the mandatory real-binary test without either configured executable path and confirm it fails rather than skips.                                             |
| Namespace cardinality    | Issue concurrent requests for one Namespace; observe one real ready OpenClaw gateway and one driver-owned route guard.                                           |
| Revision isolation       | Reject an unsafe Namespace path before bootstrap; prepare the same revision concurrently and observe one isolated Codex app-server.                              |
| Gateway configuration    | Verify the isolated gateway configuration has permissions `0600`, disables the public control UI, and preserves the real `/readyz` response.                     |
| Activation ordering      | Reject inactive and direct workload requests; after activation, forward through the authenticated guard and preserve the real gateway's native response.         |
| Real-binary proof        | Start the pinned OpenClaw gateway and complete the real Codex app-server initialization handshake without provider credentials or model inference.               |
| PostgreSQL composition   | Admit and activate a revision through the PostgreSQL-backed API and worker using the same injected real-binary Compute Driver and Harness.                       |
| Deterministic cleanup    | Retire the revision and delete its Namespace; confirm their owned runtimes disappear and their directories are removed.                                          |
| Production isolation     | Verify the production controller build excludes local-test sources, the dedicated no-emit project passes strict typechecking, and production never selects them. |

Run the mandatory real-binary integration suite with `OCC_TEST_CODEX_BIN` and
`OCC_TEST_OPENCLAW_BIN` set to pinned, executable Codex and OpenClaw paths. Run
the PostgreSQL composition suite against an isolated disposable database with
those same binary paths. The real-binary integration suite must fail rather
than skip when either path is absent. Neither suite supplies provider
credentials or proves model inference. Also verify formatting, generated
OpenAPI contracts, workspace boundaries, strict local-test typechecking,
production-build exclusion, and Git whitespace.

Format this nested specification directly with the installed Prettier binary;
the root formatting script does not include `specs/**`.
