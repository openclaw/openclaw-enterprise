# Feature Spec: Milestone 1.6 — Agents and Immutable AgentRevisions

## Problem and Decision

Agents already have stable identities and immutable revision storage, but they
cannot retain editable configuration or deploy through the public API. Milestone
1.6 adds persisted `Agent.draft_spec`, explicit authorized deployment, immutable
admission, and revision execution through the existing PostgreSQL controller and
unified `ComputeDriver`.

The platform has no production consumers. Use one canonical pinned revision
admission path; do not retain compatibility helpers, unpinned historical
revision shapes, alternate admitted snapshots, or migration fallbacks for
earlier local development state.

Build on implemented [PostgreSQL persistence](1.3-postgresql-persistence.md),
[Namespace and IAM](1.4-bootstrap-namespaces-iam.md), and
[OCC controller](1.5-occ-controller.md) specifications. The
[platform design](../../../../docs/design.md)
remains authoritative. A server-selected versioned Harness descriptor replaces
a new Harness platform resource; sandbox Drivers, executable local gateways,
and production workload authentication remain later work.

## Scope

### Changes

- Persist mutable `Agent.draft_spec`; expose authorized Agent creation, draft
  replacement, and reads without creating infrastructure work for draft edits.
- Admit one immutable revision from the saved draft, selected Harness
  descriptor, existing workload identity, and selected Compute implementation.
- Make deployment and revision reads real public API operations with attributable
  authorization and audit evidence.
- Extend the existing polling worker to prepare and retire revisions while
  preserving Namespace lifecycle processing and independent per-Agent lanes.
- Activate at most one ready revision per Agent through the existing
  `active_revision_id` pointer; preserve the prior workload when candidate
  preparation fails before predecessor retirement.

### Does not change

- The singleton Installation, exact `namespaceId` ownership, existing IAM and
  Compute capabilities, or OCC ownership of resources, identity, and readiness.
- Exactly one gateway per Namespace; provisioning and teardown remain exclusively
  `ComputeDriver.ensureNamespace` and `deleteNamespace` operations.
- The existing revision-immutability trigger, stable Agent workload identity,
  PostgreSQL polling, claim leases, fencing, retry bounds, and per-Agent locking.
- Sandbox Drivers or policies, separate Harness/Gateway/Identity resources,
  executable local gateways or child processes, Kubernetes ServiceAccounts,
  production workload authentication, external integrations, and `legacy/`.

## Implementation

1. Extend [domain contracts](../../../../packages/contracts/src/index.ts),
   [API resource schemas](../../../../packages/contracts/src/api/resources.ts), and
   [route registration](../../../../packages/contracts/src/api/routes.ts) with
   `Agent.draft_spec`, exact Agent draft updates, accepted deployment, and real
   revision responses; regenerate the checked-in OpenAPI contract.
2. Update the [PostgreSQL schema](../../../../packages/occ/src/state/postgres-schema.ts)
   and add one reviewed migration for `agents.draft_spec`, its JSON-object
   constraint, its narrow update grant, and the authoritative
   `agent_revisions_admitted_snapshot` constraint; tighten the existing queue
   shape constraint to reject metadata-only Agent work while preserving its
   columns, immutable revision rows, owner constraints, and Namespace work.
3. Extend [repository ports](../../../../packages/occ/src/state/platform-state.ts),
   the [PostgreSQL adapter](../../../../packages/occ/src/state/postgres-state.ts),
   and the in-memory adapter with persisted draft updates, complete admitted
   snapshots, exact revision reads, compare-and-set activation, and existing
   revision work.
4. Implement authorized Agent draft mutation and atomic deployment in
   [OCC](../../../../packages/occ/src/index.ts) and the
   [HTTP controller](../../../../apps/controller/src/index.ts); select one fixed
   versioned Harness descriptor and add only the required Agent `update` grant
   in [PostgreSQL development composition](../../../../apps/controller/src/composition/development-postgres.ts).
5. Extend the [controller worker](../../../../apps/controller/src/worker.ts) to
   process each candidate's preparation, predecessor retirement, and activation
   through one existing queue item with current authorization, pinned Compute
   identity, existing leases, per-Agent exclusion, and fenced activation;
   preserve Milestone 1.5 Namespace behavior without adding queue columns.
6. Extend [contract coverage](../../../../tests/conformance/contracts.test.mjs),
   [controller lifecycle coverage](../../../../tests/integration/controller-lifecycle.test.mjs),
   [PostgreSQL restart coverage](../../../../tests/integration/postgres-restart-recovery.test.mjs),
   and [real API/worker coverage](../../../../tests/integration/postgres-platform-state.test.mjs)
   for draft isolation, immutable snapshots, exact authorization, replacement,
   retries, failure, and two-Namespace ownership.

## Verification

| Required outcome      | How to verify                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Persisted Agent draft | Create and update `draft_spec`; restart the API; verify the saved draft survives without queueing infrastructure work.               |
| Exact authorization   | Reject missing Agent `update`/`deploy`, revoked bindings, exact Restrictions, foreign Namespace ownership, and wrong-owner reads.    |
| Admission atomicity   | Inject revision, queue, or audit failures; verify no partial admitted revision or Driver effect.                                     |
| Immutable snapshot    | Deploy, edit `draft_spec`, and deploy again; verify distinct revision numbers and unchanged deep-copied historical snapshots.        |
| Selected runtime      | Verify pinned Harness descriptor and Compute identity; reject missing or changed selections without fallback or revision mutation.   |
| Namespace gateway     | Reject deployment until the Milestone 1.5 worker marks the exact Namespace ready; deployment never calls `ensureNamespace`.          |
| Stable identity       | Verify one persisted workload identity per Agent, distinct sibling identities, and identical identity across that Agent's revisions. |
| Activation            | Prepare a new candidate, retire its predecessor, and observe exactly one owner-correct active revision.                              |
| Failure isolation     | Fail preparation before retirement; retain the previous pointer and workload, sibling Agents, exact gateway, and audit consistency.  |
| Retirement recovery   | Fail fencing after retirement; temporarily retain the old pointer, recover the same candidate item, and fence final activation.      |
| Superseded revision   | Retry an older revision after a newer revision activates; preserve the newer pointer and prohibit stale Compute effects.             |
| Recovery              | Restart the worker or expire a claim; verify bounded idempotent recovery, unchanged semantic keys, and rejected stale completion.    |
| Tenant isolation      | Deploy independent Agents across two Namespaces; verify no identity, revision, work, or Compute observation crosses tenants.         |
| Deferred capabilities | Verify Driver capabilities remain IAM/Compute only and no local gateway process, SandboxDriver, or workload credential is created.   |
| Workspace quality     | Run direct Node PostgreSQL/integration, TypeScript, OpenAPI, workspace-boundary, and formatting checks without a package manager.    |
