# Milestone 1.2: Initial OCC API

## Problem and Decision

Milestone 1.2 implements Milestone 2 from
`ref/milestones.md`:
a loopback-only OCC HTTP API for one Installation, multiple Namespaces, and
provisional Agents. It must have a consistent wire contract, server-owned
Namespace scope, exact authorization, replaceable admission, and attributable
audit evidence without claiming production durability or identity assurance.

The selected design is:

- Fastify 5 for HTTP routing and lifecycle.
- TypeScript 6.0.3 and `typebox` 1.x for executable JSON Schema contracts and
  `Type.Static` application types.
- `@fastify/type-provider-typebox` for typed handlers, `ajv-formats` for string
  formats, and `@fastify/swagger` for generated OpenAPI 3.1.
- Explicit constructor/factory injection. No DI container is needed for this
  milestone.
- An OCC-internal `PlatformStateStore` with a transactional in-memory adapter.
  Persistence is not a `DBDriver`.
- Injected admission, IAM, state, audit, clock, and ID ports so PostgreSQL and
  OAG can replace development adapters later without changing use cases.

[`docs/design.md`](../../../../docs/design.md) is authoritative for ownership,
trust, authorization, failure, and audit boundaries. The current implementation
at commit `2c81d97cdf027e62687cdcfe22914c53af1e5b4f`
is implementation evidence, not architecture authority. It uses raw Node HTTP,
handwritten validation, direct process-local Maps, inline development admission,
and a separate in-memory audit sink. This milestone replaces those seams while
preserving the existing domain-level revision lifecycle for later milestones.

## Scope

In scope:

- The eleven provisional routes listed below.
- One Installation per running deployment.
- Process-local Namespace and provisional Agent state.
- Canonical TypeBox schemas, common responses/errors, and generated OpenAPI.
- Server-resolved ownership and exact authorization through the selected
  `IAMDriver`.
- Loopback-only development admission for explicitly provisioned identities.
- Attributable audit for bootstrap, successful mutations, and authorization
  denials.
- Atomic in-memory mutation and audit staging.

Out of scope:

- Multiple Installations or `POST /installations`.
- A public compatibility guarantee, generated SDK, console, or tenant
  self-service API.
- PostgreSQL, migrations, restart durability, multi-process safety, durable
  audit, or durable work queues. Milestone 3 owns these.
- Production OAG transport/evidence, trusted ingress, mTLS, replay protection,
  or external IdP integration.
- Non-loopback deployment, Namespace/gateway readiness, reconciliation,
  workload identity, or complete AgentRevision deployment. Milestones 4–6 own
  these.

### Preserved Milestone 2 checklist

The implementation and proof must close these source checklist items without
changing their wording:

> - [ ] Define request validation, response shape, resource identifiers, and
>       consistent failure responses for the provisional endpoints.
> - [ ] Model one Installation per deployment. Do not add `POST /installations` or
>       treat an Installation as a tenant collection served by the same deployment.
> - [ ] Resolve Namespace ownership server-side and reject cross-Namespace access.
> - [ ] Require an explicitly provisioned development identity and authorize the
>       exact resource operation through the selected `IAMDriver`.
> - [ ] Keep the initial development admission mechanism local-only and replace it
>       with OAG verification before exposing a nondevelopment deployment.
> - [ ] Emit attributable audit events for bootstrap, successful mutations, and
>       authorization denials.

## Implementation

1. Add the contract stack. `packages/contracts` directly depends on `typebox`;
   `apps/controller` directly depends on Fastify, Swagger, the TypeBox provider,
   TypeBox, and `ajv-formats`. Keep TypeScript/tooling at the root and verify the
   pnpm lockfile satisfies provider peers. Add TypeBox common/resource/route
   modules, deterministic OpenAPI generation, and one error mapper.
2. Replace direct Maps with `PlatformStateStore`, aggregate repositories, and
   the serialized clone-on-write memory adapter. Move bootstrap and ownership
   invariants into the store contract while preserving lower-level revision
   domain behavior.
3. Add admission and request-context ports plus development/test/production
   composition roots. Replace caller-supplied identity headers with configured
   local bearer mappings and keep Driver selection server-owned.
4. Add the audit factory/repository and stage required success events with
   mutations. Bind the eleven handlers from the registry and migrate existing
   HTTP deploy/revision tests to `409`/empty/`404` behavior.

Primary files are `packages/contracts/src/api/*`,
`packages/occ/src/state/*`, `packages/occ/src/services/*`,
`packages/audit/src/*`, `apps/controller/src/admission/*`,
`apps/controller/src/composition/*`, and `apps/controller/src/http/*`.
`apps/controller/src/server.mjs` becomes configuration plus composition only.

## Verification

Milestone 2 is complete when focused tests prove:

- Exactly eleven routes exist; their registered TypeBox schemas, handler
  response statuses, and deterministic OpenAPI 3.1 artifact agree.
- Strict validation rejects extra/wrong fields, invalid IDs/formats, query
  parameters, disallowed bodies, unsafe/deep configuration, wrong media types,
  and bodies over 64 KiB before domain side effects.
- Duplicate and concurrent bootstrap have one winner; name/ID conflicts do not
  overwrite state; thrown work or audit leaves the prior snapshot unchanged.
- All repository lookups use compound ownership keys and return immutable
  values. A reusable conformance suite can run against PostgreSQL in M3.
- Development startup/request checks reject nondevelopment, public,
  nonloopback, proxied, missing, malformed, unknown, and ambiguous admission.
- IAM spies receive the exact coarse action and full server-resolved target for
  every route and list candidate. IAM outage/invalid decisions fail closed.
- Two Namespaces with distinct grants cannot discover or mutate each other's
  resources; wrong-parent IDs return `NOT_FOUND` without foreign details.
- Authorized deploy returns `409`, revision list is empty, exact revision is
  `404`, and no M2 HTTP request creates revision/work state. Existing direct
  domain revision tests still pass.
- Required bootstrap, successful-mutation, and authorization-denial audit events
  occur exactly once, identify the correct actor and exact resource, contain no
  prohibited data, and obey rollback/fail-closed behavior. Unauthenticated
  admission failures create no audit event or other side effect.
- The server binds only loopback, restarts without retained state, and documents
  that PostgreSQL and OAG guarantees are not yet delivered.

Run focused formatting, typecheck, build, contract/OpenAPI, repository,
admission, audit, security, and HTTP integration suites. Do not run or import
`legacy/`.
