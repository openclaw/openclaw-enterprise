# Strands Box pilot validation

The pilot exercises released Box v0.2.1 and Codex 0.164.0. The tests below cover different paths.

| Check                                                             | Observed result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Standalone native endpoint on emulated ARM Linux                  | The original endpoint rejected missing and incorrect authentication, then initialized with valid authentication. A direct native command wrote a workspace marker and an independent read matched it. Attempts to read or write a sibling file were refused and its bytes stayed unchanged.                                                                                                                                                                                                                                              |
| Ordinary Gateway chat with a controlled model                     | A separate prototype sent an ordinary chat through the Gateway and ran a workspace tool inside the original Box. An independent check matched the workspace and marker. The alternate shell argument and sibling read and write attempts were refused.                                                                                                                                                                                                                                                                                   |
| Public read-only workspace tool in a controlled Gateway chat      | An ordinary chat with a synthetic model exercised the declared tool from `3f7bd36bb64e3c1c92a39e50b5eed8035bbcd688`. An independent check matched the marker file’s device, inode and digest; the file stayed unchanged. Stock Box recorded one named permit and one default denial for the alternate argument. A separate native check refused sibling reads and writes and confirmed unchanged bytes. The Gateway used a separate controlled setup. This result does not establish the same outcome on the later public runtime image. |
| Gateway built from the published branch with the original ARM Box | A separate host built and verified the 26-layer AMD64 Gateway image from `c9e23c076fb836f1bbca5a09afb6039301768cd9`. The original ARM Box endpoint accepted valid authentication and initialized its native session. The Gateway accepted one chat from the stock CLI. The client reported a restricted-policy refusal. No terminal tool result, assistant answer or persisted native thread for the turn was found during observation. The failing method was not identified.                                                           |
| OCE installation bootstrap on ARM K3s                             | The API and Worker built from branch ancestor `0e86e99b` both reached Ready. The Worker reached Ready after its existing marker probe was given ten seconds instead of one. Authenticated `GET /installation` returned HTTP 200. The normal API created the first Namespace, and an independent Kubernetes read confirmed it. This bootstrap did not deploy a Box Agent.                                                                                                                                                                 |
| Hosted native ARM smoke                                           | The first run stopped at Box startup with an unclassified failure. The second exposed the failure stage as executable mount inventory. Both stopped before native verification. See the [first run](https://github.com/openclaw/openclaw-enterprise/actions/runs/42165954170) and [second run](https://github.com/openclaw/openclaw-enterprise/actions/runs/42167069747).                                                                                                                                                                |

The direct native verifier supplies its workspace, executable and external sandbox policy explicitly. A model-driven turn must also carry the admitted workspace and policy through the Gateway and select a permitted executable. Earlier controlled chats stopped at namespace setup, marker access or the executable check even though direct native verification passed.

## What AWS can reproduce now

1. Start with the [host preparation and two-terminal native check](README.md#prepare-the-host-and-verify-box) as a nonroot user on a dedicated ARM64 Linux host. The [automation script](verify-native-ci.sh) checks the exact checkout and pinned artifacts, runs the native verifier, and cleans up. A hosted runner may stop at mount inventory before verification.
2. Use the [controlled Gateway chat procedure](ordinary-chat/README.md) to exercise the same tool and collect the original tool and file evidence. Treat chat acceptance as an intermediate step. A successful check requires the tool result and independent file verification described in that procedure.

An installed Agent still needs to complete ordinary chat and a workspace command, push to its assigned repository, and create a PR. It must also be denied an unassigned repository and lose Git access after withdrawal while the original chat continues. Live GitHub verification remains open.
